Challenges for PE support

File 01 · System

Complex Legacy System

  • Poorly structured, hard to navigate
  • Troubleshooting takes disproportionate time
File 02 · Process

Time-Consuming Investigation

  • Manual review to gather relevant info per case
  • Every case starts from a blank slate
File 03 · Approach

Reactive, Not Proactive

  • Investigation starts only after issues are raised
  • Historical knowledge isn't used upfront
File 04 · Discovery

Previous Fixes Are Hard to Find

  • Fix may already exist in Jira or with another engineer
  • Comments often lack the technical "how" and "why"
File 05 · Duplication

Repeated Investigation

  • Recurring issues re-investigated from scratch
  • Past-case knowledge rarely reused
File 06 · Evidence

Same evidence hunt on most cases

  • Airflow task logs
  • S3 data presence · SecAPI levels · DB1 checks
  • Codebase + prior tickets · pod status
File 07 · Knowledge

Hard to Retain & Transfer

  • Scattered across chats, files, individual heads
  • New engineers face a long ramp-up
Target

Where Sherlock steps in

Automate the repeatable hunt and capture the fast path, so every case starts from a playbook — not from scratch.
