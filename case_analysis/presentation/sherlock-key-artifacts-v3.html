Distill, then Playbook

→
Step 1

Distill

Distill is how Sherlock learns from a completed investigation.

After a case finishes, it records:

  • What evidence solved the case
  • What checks wasted time
  • What pattern may appear again
  • Whether a playbook should be created or updated

Example: In the Reuters price investigation, checking SecAPI and the Reuters files solved the case. Checking Airflow or Helix was unnecessary.

Distill adds:

  • SecAPI and Reuters files to the playbook's recommended steps
  • Airflow and Helix to its skip list

The next similar investigation can therefore start with the useful checks.

Distill only updates Sherlock's investigation memory. It does not change production data or post anything to Jira.

Step 2

Playbook

A playbook tells Sherlock how to investigate a type of problem.

It contains:

  • When this investigation path should be used
  • What to check first
  • What evidence to collect
  • What checks can be skipped
  • When to stop investigating

Example: A futures price changes overnight.

The playbook tells Sherlock to:

  1. Check the old and new prices.
  2. Check SecAPI history.
  3. Check the Reuters source files.
  4. Confirm whether Reuters corrected the price.

If these records agree, Sherlock can skip Airflow, Helix, and broad code searches because they will not explain where the price came from.
